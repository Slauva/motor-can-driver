# Поддерживаемая часть LK-TECH CAN V2.35

Источник: [локальный PDF V2.35](<LK-TECH motor control protocol(CAN) V2.35.pdf>).
Ссылки ниже указывают напечатанные номера страниц. Реализация рассчитана на
одиночные команды моторам MF/MG и совместимым устройствам с проверенной шкалой
iq. Названия Python API описывают функцию устройства, а совместимость задаётся
этим протоколом.

## Кадр и транзакция

По с.5: CAN classic, стандартный 11-битный ID, data frame, DLC=8.
Номер узла 1–32 задаёт ID `0x140 + node_id` в запросе и ответе.
Все многобайтовые числа передаются младшим байтом вперёд. В таблицах
`data[a:b]` — срез Python, последний индекс не входит.

Обычный запрос чтения содержит команду в байте 0 и семь нулей.
Транспорт отправляет команду один раз и ожидает подходящий RX-кадр с тем же ID
и ожидаемым opcode. TX echo, extended, remote, error и CAN-FD кадры не считаются
ответом мотора. У совпадающего ответа проверяется длина 8 байт.
Тайм-аут включает получение общей блокировки, удаление накопленных кадров,
отправку и ожидание ответа. В PDF указано время ответа до 0.25 мс; тайм-аут
Python учитывает также USB и планировщик ОС и не является real-time гарантией.

Все узлы одной шины должны делить один `CanTransport`. Перед отправкой
транспорт удаляет до 256 накопленных кадров за время не более 20 мс; если очередь
не опустела, запрос отклоняется без отправки. При этом потребляются также кадры
других ID: транспорт предназначен для выделенного обмена этим протоколом.
Очистка не устраняет кадры, ещё находящиеся в пути. Номера транзакции в протоколе
нет, поэтому после тайм-аута нельзя гарантировать свежесть следующего ответа
с тем же ID/opcode. Автоматических повторов нет.

## Команды реализации

| Команда | Запрос / ответ | PDF |
|---|---|---:|
| `80` OFF | Семь нулей; ответ повторяет запрос. Сбрасывает предыдущую команду и обороты | 5 |
| `88` RUN | Семь нулей; ответ повторяет запрос | 5–6 |
| `81` STOP | Семь нулей; ответ повторяет запрос. Сохраняет состояние мотора | 6 |
| `A1` iq | `data[4:6]`: int16, raw −2048…2048. Остальные поля нулевые. Ответ — `Feedback` | 7–8 |
| `A2` скорость | `data[4:8]`: int32, 0.01 °/с. Ответ — `Feedback` | 8 |
| `A4` позиция | `data[2:4]`: uint16, 1 °/с; `data[4:8]`: int32, 0.01°. Ответ — `Feedback` | 9 |
| `9A` защита | Температура int8 в `[1]`; напряжение uint16 в `[3:5]`, 0.1 V; ошибки uint8 в `[7]` | 17–18 |
| `9B` сброс ошибок | Ответ как 9A; допускаются opcode 9A и 9B | 18–19 |
| `9C` состояние | Ответ — `Feedback`, отдельная шкала iq | 19–20 |
| `9D` фазные токи | Температура int8 в `[1]`; int16 фаз A/B/C в `[2:4]`, `[4:6]`, `[6:8]`, 1/64 A | 20 |
| `90` энкодер | Три uint16 в `[2:4]`, `[4:6]`, `[6:8]`: позиция, исходная позиция, смещение | 14–15 |
| `92` многовитковый угол | Семь байт `[1:8]`, signed, 0.01°, положительное направление CW | 16 |
| `94` одновитковый угол | uint32 в `[4:8]`, 0.01°, raw 0–35999, увеличение CW | 17 |
| `30` PID | Шесть uint8 в `[2:8]`: position P/I, speed P/I, current P/I | 12 |
| `31` PID в RAM | Те же поля; ответ повторяет запись | 13 |
| `33` ускорение | int32 в `[4:8]`, 1 °/с² | 13–14 |
| `34` ускорение в RAM | int32 в `[4:8]`, 1 °/с²; ответ повторяет запись | 14 |

`Feedback`: `data[1]` — int8 температуры, `data[2:4]` — int16 iq,
`data[4:6]` — int16 скорости **1 °/с**, `data[6:8]` — uint16 энкодера.
В кадре скорость передаётся в градусах в секунду. API сохраняет её как
`Feedback.speed_dps` и предоставляет вычисляемое свойство `Feedback.speed_rpm`:
**1 RPM = 6 °/с**. Разрешение измерения остаётся 1 °/с, то есть 1/6 RPM.
Ток iq не равен фазному току или току источника питания. Перевод в момент
требует параметров двигателя, которых в PDF нет.

Биты защиты 9A: `0x01` — пониженное напряжение, `0x08` — перегрев.
Любой ненулевой байт ошибки, включая неизвестные биты, запрещает движение.
Ошибка не сбрасывается, пока причина остаётся активной (с.19).
Температура во всех ответах signed: например, `0xFB` означает −5 °C.

## Шкала тока и ограничения

Для A1 и ответов команд движения на с.7 даны MF ±16.5 A и MG ±33 A при
raw ±2048. На с.19 для отдельного чтения 9C указано ±33 A без разделения серий.
`CurrentScale` хранит обе шкалы раздельно:

```python
MF_CURRENT_SCALE = CurrentScale(full_scale_a=16.5, status_full_scale_a=33.0)
MG_CURRENT_SCALE = CurrentScale(full_scale_a=33.0, status_full_scale_a=33.0)
```

Это буквальное следование таблицам с явной неоднозначностью для MF.
Если проверенная документация конкретной прошивки определяет 9C иначе,
задайте обе шкалы явно. Для MH численное соответствие raw/A в PDF отсутствует.
Нельзя подставлять допустимый рабочий ток вместо коэффициента шкалы.

Команда iq переводится в raw как `current_a * 2048 / full_scale_a` с усечением
к нулю. Независимый `max_current_a` проверяется **до** кодирования.
С.7 прямо указывает, что A1 не ограничивается параметром Max Torque Current
фирменного инструмента. Поэтому проверка на стороне Python обязательна.

Скорость/позиция ограничиваются настройкой максимального тока в прошивке
(с.8–9). Команд установки/чтения этой настройки в V2.35 нет.
`firmware_current_limit_a` — декларация заранее проверенной настройки,
а не запись регистра. Без неё соответствующие режимы закрыты.
Перед скоростью/позицией читается ускорение: оно должно находиться в диапазоне
от 1 до `max_acceleration_dps2`. Этот же предел применяется к явной записи
ускорения в RAM. Автоматических записей настройки нет.

`MotorLimits` принимает предел скорости как `max_speed_dps` либо
`max_speed_rpm`; одновременно задавать оба нельзя. По умолчанию предел
равен 30 °/с, то есть 5 RPM. `set_speed_rpm()` переводит знаковую скорость
в °/с для той же команды A2 и применяет общий предел скорости до отправки.
`set_speed()` сохраняет аргумент в °/с. Функции `rpm_to_dps()` и `dps_to_rpm()`
позволяют выполнить этот пересчёт явно. Единицы и формат CAN-кадров не меняются.

Позиция всегда задаётся A4 с явной границей скорости. Скорость A4 имеет
разрешение **1 °/с**, хотя скорость A2 — **0.01 °/с**.
`set_position()` принимает `max_speed_dps` либо `max_speed_rpm`; без аргумента
использует общий предел из `MotorLimits`. После перевода RPM в °/с скорость A4
округляется вниз, минимальный код — 1 (1/6 RPM). Положение в градусах и скорость
в RPM относятся к системе координат самого мотора; преобразование через редуктор
и механические границы приложения задаёт разработчик стенда.

`enable()` сначала отправляет OFF, затем проверяет защиту и отправляет RUN.
Запись параметров в RAM и явный сброс ошибок также сначала подтверждают OFF;
они доступны только при снятом локальном разрешении движения.
По с.5 OFF очищает накопленные обороты и прежнюю команду. Поэтому новый сеанс
не сохраняет прежнюю многовитковую координату; нельзя повторять абсолютную цель
после повторного включения без проверки новой системы отсчёта.

## Неоднозначности и исключённые операции

| Место PDF | Неоднозначность / решение |
|---|---|
| С.16, 92 | Тип назван int64, но таблица передаёт только семь байт. Декодируется signed 56-bit с расширением знака |
| С.18–19, 9B | Запрос 9B, таблица ответа содержит 9A. Принимаются оба значения |
| С.7 и 19 | Разные указания шкалы iq MF для ответа A1 и 9C. Шкалы отдельные, требуется проверка прошивки |
| С.12–13, PID | Физических коэффициентов пересчёта нет. API возвращает/принимает шесть исходных байтов |
| С.14–15 против с.7 | Чтение 90 описывает 14 бит, ответы движения — 14/15/18 бит. Отсчёты возвращаются без предположений об обороте |
| С.11–12, A8 | Проза называет maxSpeed uint32, таблица отводит два байта. Команда не поддерживается |

ROM-записи 19/91/32, команда 95 с пометкой недоступности, open-loop MS,
single-turn/increment перемещения и broadcast в текущий публичный API не входят.
На с.15 для команды записи текущего нуля 19 указаны износ ROM и применение
после перезапуска питания. Автоматическое обнуление при запуске поэтому
не выполняется. Broadcast использует другой режим и шкалу тока; PDF запрещает
смешивать его с single-motor командами (с.20–21).

PDF не задаёт watchdog связи, аппаратный аварийный останов, номера транзакций,
автоопределение прошивки или коэффициент редуктора. Пропажа связи не доказывает
остановку. Хост проверяет телеметрию при вызовах API; это дискретные проверки,
а не независимый аппаратный контур защиты.
