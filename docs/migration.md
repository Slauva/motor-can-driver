# Переход с `packages.driver` на `can_motor` 0.2

Версия 0.2 меняет публичный API. Импорты `packages.driver`, `DRC06`, `Gyems`
заменены на `can_motor.Motor` и отдельный `CanTransport`. Прежние значения
и единицы нельзя переносить механически; совместимость со старым API
не сохраняется.

## Соответствие API

| Ранее | Теперь |
|---|---|
| `CanBus(bustype="socketcan", ...)` с настройкой ОС | Настроить интерфейс отдельно, затем `CanTransport.socketcan("can0")` |
| `CanBus(bustype="gs_usb", channel=0, ...)` | `CanTransport.gs_usb(channel=0, bitrate=1_000_000)` |
| `Gyems(bus, motor_id=0x141, max_torque=6)` | `Motor(transport, node_id=1, current_scale=..., limits=...)` |
| `max_torque` одновременно как шкала и предел | `CurrentScale` — коэффициенты протокола; `MotorLimits.max_current_a` — предел стенда |
| `enable()` с автоматическим сбросом ошибки | `enable()`: OFF, проверка состояния, RUN; сброс только явным `clear_errors()` |
| `disable(True)` | `disable()` — команда OFF; `stop()` — STOP |
| `set_current(...)` / низкоуровневый `set_torque(...)` | `set_current(current_a)` в амперах iq |
| `set_speed(...)` | `set_speed(speed_dps)` в °/с |
| `set_angle(...)` и варианты | `set_position(position_deg, max_speed_dps=...)`, абсолютное многовитковое положение A4 |
| `read_angle(single_circle=True)` | `read_angle(single_turn=True)` |
| `info()` и изменяемый словарь | Отдельные `read_health()`, `read_feedback()`, `read_phase_currents()` и неизменяемые dataclass |
| `read_encoder()` с подсчётом оборотов | `read_encoder()` с исходными отсчётами; для угла — `read_angle()` |
| `PID` с пересчитанными float | `PidParameters` с шестью исходными uint8 |
| `write_pid(..., storage=...)` | `write_pid_ram(parameters)` |
| `write_acceleration(...)` | `write_acceleration_ram(acceleration_dps2)` |
| Автоматическое `set_zero()` | Нет автоматической смены нуля и ROM-записей |

## Минимальный переход

```python
from can_motor import CanTransport, MG_CURRENT_SCALE, Motor, MotorLimits

with CanTransport.socketcan("can0") as transport:
    motor = Motor(
        transport,
        node_id=1,
        current_scale=MG_CURRENT_SCALE,  # только после проверки профиля устройства
        limits=MotorLimits(max_current_a=0.3),
    )
    print(motor.read_health())
    with motor.control():
        print(motor.set_current(0.2))
```

Для нескольких моторов создайте один транспорт и несколько `Motor` с разными
номерами. Не передавайте один `python-can.Bus` нескольким независимым транспортам.
Контекст `motor.control()` отвечает за попытку OFF; контекст транспорта —
за освобождение адаптера. Перед включением отправляется OFF, который по PDF
сбрасывает накопленные обороты и предыдущую команду. После повторного включения
проверьте начало отсчёта перед абсолютным позиционированием.

Для скорости/позиции требуется дополнительно передать
`firmware_current_limit_a` в `MotorLimits`. Сначала настройте и проверьте этот
предел внешним инструментом; числовое значение Python его не программирует.
Перед движением также проверяется настройка ускорения. Остальные возможности
и подготовка адаптеров описаны в [README](../README.md).

## Исправленные несовпадения

| Прежнее поведение | Изменение |
|---|---|
| Ток задавался относительно произвольного `max_torque=6`, а команда A1 использовала raw ±2000 | Отдельный масштаб raw ±2048 из V2.35 и независимый предел тока |
| Скорость телеметрии называлась RPM и дополнительно делилась на 10 | Возвращается исходная скорость в °/с |
| Одновитковый угол читался из двух последних байтов как signed | uint32 из байтов 4–7, 0.01°, проверка диапазона |
| Температура читалась как unsigned | signed int8, включая отрицательные значения |
| Проверка защиты работала со строковыми ключами словаря и неверными битами | Битовые маски 0x01/0x08 и запрет при любом ненулевом байте ошибки |
| Параметры PID пересчитывались в физические коэффициенты без основания в PDF | Исходные байты 0–255 |
| Энкодер разворачивался по любому уменьшению показания | Возвращаются отсчёты без предположений о направлении и разрешении |
| Пример записывал ноль в ROM при каждом запуске | Пример по умолчанию читает состояние; запись ROM отсутствует |
| Получение ответа проверяло преимущественно CAN ID | Проверяются ID, opcode, формат, длина, RX; запросы сериализуются |
| Открытие SocketCAN искало `/dev/ttyACM*` и выполняло `sudo` | Устройство выбирается и настраивается явно снаружи библиотеки |

Подтверждения форматов, включая различие шкалы тока MF в ответах A1/9C,
приведены в [разборе протокола](protocol.md). Старые сохранённые PID, значения
`max_torque` и вычисленные обороты нельзя считать достоверными параметрами новой
конфигурации. Перед запуском заново проверьте единицы, профиль тока, направление
и положение нуля конкретного мотора.
